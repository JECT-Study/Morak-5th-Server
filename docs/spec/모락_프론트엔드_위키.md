## 1. 서비스 한 장 요약 (FE가 알아야 할 것만)

- **모락**: 같은 목표의 사람들이 챌린지 그룹을 만들어 **매일 사진 인증**하는 웹앱. 캐릭터는 **모락이**.
- 포인트 **P**는 무료 활동 포인트다. 화면·문구 어디에도 **"보증금", "예치금", "현금", "충전", "환급", "출금"을 쓰지 않는다.** 결제·충전·출금 화면은 없다.
- 챌린지 유형은 3가지이고 **화면이 달라지는 지점이 많다**: ① 비공개 ② 포인트 없는 공개 ③ **포인트 공개**.
  - ①② 인증 판정자 = 방장·부방장, ③ = 운영진.
  - ③에서만: 판정 버튼·업무 경고·정오 자동 승인이 **없고**, 인증 직후 상태가 "검수 중"이다.
- 사용자 역할: 방장 / 부방장 / 참여자. 어드민(운영진)은 별도 화면.
- 모든 시간·날짜는 **KST**. 인증 마감 23:59, 판정 마감 다음 날 12:00, 채팅 종료·정산 등 자정 경계가 많다. 클라이언트 시계 대신 **서버 시각**으로 카운트다운한다 [제안, FE-1].

## 2. 화면 지도

```
[비로그인] 로그인/가입 → (신규) 온보딩 3화면 → 모집중 탭
[하단 내비]  내 챌린지(홈) | 모집중(탐색) | 마이페이지      ← 탭 구성은 [OPEN, FE-O1]
홈
 ├ 알림창 (우상단 종)           ├ 초대 코드 입력 (우상단)        ├ 챌린지 찾기 (홈이 비었을 때)
 ├ 챌린지 카드 → 그룹 상세 ─ 인증하기 / 판정하기 / 팀 채팅 / 부방장 역할 안내
 └ (시작 보류) 기간 다시 설정 / 폐기  — 방장 전용
모집중: 검색·필터 → 챌린지 상세 → [참여 포인트 확인] → 지원서 → 승인 대기
        └ 챌린지 만들기
챌린지 상세 ─ 지원자 관리(방장) ─ 지원자 프로필
인증 제출 / 인증 판정 / 인증 스토리 열람(답글 → 채팅)
챌린지 최종 결과
마이페이지 ─ 정보 수정 / 메달 상세 / 포인트 내역(광고 보고 받기) / 내 챌린지 전체 기록 / 승인 대기 목록 / 설정
타인 프로필 (조회 전용)
어드민: /admin/reviews (운영진, 별도 설계 필요)
```

## 3. 공통 규칙

### 3.1 뒤로가기·내비게이션 [확정]
- 별도 화면의 뒤로가기는 **좌측 상단 `<` 화살표 + 화면 제목**. 하단 "뒤로" 버튼은 쓰지 않는다. '닫기', '나가기'도 좌측 상단 `<`로 표현.
- 복귀 위치:

| 화면 | `<` 가 가는 곳 |
|---|---|
| 설정 | 마이페이지 |
| 설정 하위(약관 등) | 설정 |
| 정보 수정 | 변경 있음 → "수정한 내용을 저장하지 않고 나갈까요?" 확인 / 변경 없음 → 마이페이지 |
| 인증률·횟수 설명 팝업 | 마이페이지 |
| 메달 상세 | 마이페이지 |
| 사진 접근 거부 안내 | 마이페이지 |
| 내 챌린지 전체 기록 목록 | 마이페이지 |
| 지난 챌린지 당시 상세 | 목록 |
| 지난 인증 사진 / 채팅 기록 | 당시 상세 |
| 채팅 | 채팅에 들어온 이전 화면 |
| 인증 스토리 열람 | 기존 채팅 위치 |

- 수정 취소 확인창만 예외: **'계속 수정'**(화면 유지), **'나가기 → 변경 버리고 마이페이지'** 두 버튼. 이 창에는 `<`를 두지 않는다.
- 정의도에는 디자이너가 알 수 있게 "뒤로가기 → {이전 화면}"을 작은 글씨로 병기한다.

### 3.2 로딩·빈 상태·오류 [확정, 화면정의서 §9]
- **값을 불러오는 동안 0P·0%·0회를 임의 표시하지 않는다.** 스켈레톤/스피너를 쓴다.
- 불러오기 실패: `정보를 불러오지 못했어요.` + `다시 시도` 버튼.
- 저장 실패: 입력값·기존 사진을 유지하고 재시도 가능. 화면을 나갔다 와도 **저장 성공이 확인된 값만** 반영.
- 아래는 오류가 아니라 **정상 빈 상태**로 각각 안내한다: 기본 사진, 인증 기록 없음, 메달 없음, 보관함 없음, 승인 대기 없음, 대화 없음.
- 0P는 정상 값이다. 0P를 "없음"으로 숨기지 않는다.

### 3.3 중복 요청 방지 [제안, FE-2]
다음 동작은 버튼 연타·재진입으로 두 번 실행되면 안 된다. 요청 중 버튼 비활성 + 서버 멱등으로 이중 방어.
- 온보딩 '확인했어요'(가입 포인트 10,000P 1회), 포인트를 걸고 신청, 승인/거절, 인증 제출, 광고 보상 수령, 프로필 사진 '적용', 채팅 전송(→ `client_message_id`, 7절).

### 3.4 포인트 표기 [확정]
- 단위는 **P** (`10,000P`). 천 단위 쉼표. "사용 가능한 포인트"는 **승인 대기·참여 중 챌린지에 이미 걸린 포인트를 뺀 값**(서버가 계산한 잔액 그대로 표시, 클라이언트가 빼지 않는다).
- 타인 프로필에는 잔액·내역·획득 버튼을 **모두 숨긴다**.

### 3.5 외부 링크
관련 링크(프로필) 선택 시 해당 사이트로 이동. **외부 링크임을 식별할 수 있게 표시**(아이콘 등). 새 탭/인앱 이동 방식은 [OPEN, FE-O6].

## 4. 상태 표시 사전

### 4.1 챌린지 상태 → 홈 카드·상세 표시

| 서버 상태 | 사용자에게 보이는 말 | 카드에 보일 것 | 비고 |
|---|---|---|---|
| `RECRUITING` (정원 미달) | 모집 중 / 시작 대기 | 시작일, 인원 | 시작일은 방장도 못 바꿈 |
| `RECRUITING` (정원 가득) | 모집 마감 | 인원 N/N | `current_count == capacity`로 계산. 시작일은 그대로 |
| `START_HELD` | **시작 보류** | 현재 인원/최소 인원, 선택 기한("11월 3일 23:59까지") | 방장에게만 두 버튼 |
| `IN_PROGRESS` | 진행 중 N일차 | 진행 일차, 오늘 팀원 인증 현황, 팀 달성률 | |
| `FINALIZING` | 결과 집계 중 | — | 정산 대기. 결과 화면은 아직 없음 [제안, FE-3] |
| `ENDED` | 종료 | → 내 챌린지 전체 기록 | 홈에서는 빠짐 (진행 중인 그룹만 홈) |
| `DISCARDED` | 폐기됨 | — | 상세 진입 시 "이미 종료된 챌린지입니다" |

### 4.2 내 참가 상태 → 챌린지 상세 버튼 (**하나만** 노출) [확정, 화면정의서 §3]

| 내 상태 | 노출 버튼 | 동작 |
|---|---|---|
| 비로그인 | 로그인 유도 | 로그인 후 상세로 복귀 (초대 링크·코드 진입 시) |
| 미지원 | **지원하기** | 5개 한도 확인 → 한도 초과면 `참여 가능한 챌린지를 초과했습니다` 표시 + 신청 차단. 아니면 지원서(각오 한마디) → (포인트 공개면) 참여 포인트 확인 화면 |
| 지원 후 `PENDING` | **신청 상태 확인** | **취소 버튼 없음** |
| `ACTIVE`/`EXPEL_NOTICED` | **그룹으로 이동** | |
| 방장 | **지원자 관리** (+ 시작 보류 시 안내·두 버튼) | |
| 거절·무효 후 | 재지원 불가 | 버튼 문구 [OPEN, FE-O3] |
| 모집 마감(정원 가득) | 지원 불가 | 비활성 + 안내 문구 [제안, FE-4: "모집이 마감된 챌린지예요"] |

- **즉시 참여 버튼은 어디에도 없다.** 공개·비공개·링크·코드·포인트 유무 불문, 항상 지원서 → 방장 승인 순서.

### 4.3 인증 상태 → 라벨 [확정]

| 서버 상태 | 내 화면 라벨 | 다른 팀원 화면 | 비고 |
|---|---|---|---|
| `PENDING` (비포인트) | **보류** | 안 보임 | 판정자 대기 |
| `PENDING` (포인트 공개) | **검수 중** | 안 보임 | 운영진 대기 |
| `APPROVED` | 승인 | 피드·얼굴 탭에서 보임 | |
| `AUTO_APPROVED` | **승인과 동일하게 표시** | 보임 | 정오 자동 승인. 별도 "자동" 라벨은 정의 없음 [OPEN, FE-O9] |
| `REJECTED` | 거절 (실패) | 안 보임 | 거절 사유 없음 |
| `FAILED` | 미제출 실패 | 안 보임 | 마감 후 제출 포함 |

- **승인된 사진만 팀 피드에 노출.** 보류·검수 중·거절 사진은 다른 팀원에게 절대 보이지 않는다.
- 좋아요·답글은 인증 성공 여부에 영향 없다.

### 4.4 참가 상태 → 사용자에게 보이는 말

| 상태 | 표시 |
|---|---|
| `PENDING` | 승인 대기 (마이페이지 승인 대기 목록, 상세) |
| `INVALIDATED` | **유효한 대기로 표시하지 않음** (신청자 본인 목록에서도 제외) |
| `EXPEL_NOTICED` | 퇴장 예정 (인증 의무 없음, 인증·채팅 전송 불가 [제안, 백엔드 D-11]) |
| `EXPELLED` | 퇴장 (채팅은 퇴장 시각까지 읽기 전용) |
| `COMPLETED` | 완주 |
| `EARLY_ENDED` | 조기 종료. **완주·성공으로 표시하지 않음** |

## 5. 화면별 스펙

### 5.1 홈 (내 챌린지)
- 우측 상단: **초대 코드 입력**, 그 옆 **종 모양 알림 아이콘**(앱 내 알림창).
- 목록: 내 챌린지 개수와 카드. 카드 항목 = 현재 상태, 진행 일차, 오늘 팀원 인증 현황, 팀 달성률.
- 카드 버튼: `인증하기`, `판정하기`(방장·부방장, 비포인트 챌린지만), `팀 채팅`, 카드 선택 → 그룹 상세.
- 시작 보류 카드: `시작 보류` + 현재 인원/최소 인원 + 선택 기한. **방장에게만** `기간 다시 설정하기`, `챌린지 폐기하기`.
- 내 챌린지가 0개: `챌린지 찾기` 버튼 → 모집중 (특히 필요).
- 홈 카드에서 **팀원 얼굴을 누르면** 승인된 오늘 인증 사진을 본다.
- 비로그인 사용자의 홈 [OPEN, FE-O2 / 화면정의서 "어떻게 보여줄건지"].

### 5.2 모집중 (탐색)
- 검색창, 카테고리·필터. 카테고리는 운동·공부·커리어·독서·생활습관(온보딩 관심 분야와 같은 목록, 단 "검색 카테고리와 구분").
- 목록 항목: 카테고리, 제목, 기간, 시작일, 인증 방법, 참여 포인트, 인원.
- 노출 대상: **모집 중인 공개 챌린지만**. 비공개는 노출하지 않는다.
- `챌린지 만들기` 버튼.
- 비로그인 탐색 범위 [OPEN, FE-O2]. 검색은 MVP에서 서버 DB 검색(실시간 자동완성 등 기대하지 않는다) [제안].

### 5.3 챌린지 상세
- 진입 경로: 탐색(공개만), 초대 링크, 초대 코드. 모든 경로 동일하게 **상세 확인 → 지원서 작성·지원하기 → 방장 승인 → 참여 확정**.
- 보여줄 것: 개설 정보 전체 + **판정 방식, 퇴장 기준, 포인트 반환 규칙 안내**. 현재 참여자의 프로필 조회 가능.
- 버튼은 4.2 표.
- 오류 문구 [확정]:

| 상황 | 문구 |
|---|---|
| 유효하지 않은 초대 코드 | `유효하지 않은 코드입니다` |
| 유효하지 않은 초대 링크 | 유효하지 않은 접근임을 안내 (문구 [OPEN, FE-O4]) |
| 종료·폐기된 그룹에 코드/옛 링크로 진입 | `이미 종료된 챌린지입니다` + 신청·합류로 진행하지 않음 |

- 초대 코드 길이: 미정 → **입력 길이를 하드코딩하지 않는다**. (6자리는 예시일 뿐)
- 시작 보류 상태면 상세 **상단**에도 보류 안내와 방장 두 버튼 표시(알림을 읽었는지와 무관).

### 5.4 참여 포인트 확인·획득 (공개+포인트 챌린지 신청 시)
- 보여줄 것: 이 챌린지 참여 포인트(1,000~5,000P), **현재 잔액**, 정산·퇴장 시 전액 차감 안내.
- 버튼: `포인트를 걸고 신청` → **승인 대기**(이 단계에서는 채팅 접근 불가).
- **잔액 부족**: 신청을 완료시키지 않고 광고·앱 방문 출석으로 포인트 얻는 방법을 안내. 결제 유도 금지.
- `광고 시청` → 광고 화면 → 완료 여부에 따라 보상 지급 → 이 화면(또는 포인트 내역)으로 복귀.
- 반환 시점 안내(화면에 같이 표시): 방장 거절·시작 전 폐기·5개 한도 무효화 = **처리 즉시 전액 반환**. 진행 중 인원 미달 조기 종료 = 결과 화면의 개인별 정산.
- 포인트 없는 챌린지는 이 화면을 건너뛰고 지원서만 쓴다. 잔액이 0P여도 지원 가능.
- 첫 가입 10,000P, 광고 1회 500P·하루 최대 5회, 출석 100P, 30일 연속 출석 당일 총 3,000P.

### 5.5 지원자 관리 (방장)
- 목록: 닉네임, 메달, 지원 메시지, **현재 인원/정원**. 버튼: `프로필 보기`, `승인`, `거절`, `초대 링크 공유`.
- **승인/거절은 유효한 신청에만** 가능하다.
- 한도 초과로 무효화된 신청: 방장에게 알림 + 안내 `해당 사용자가 참여할 수 있는 챌린지가 초과되었습니다.` + `확인` 버튼. **확인 전에도 승인 불가 상태**로 보이고, 확인하면 목록에서 사라진다. (포인트 반환은 확인과 무관하게 이미 끝남)
- 승인으로 정원이 차면 남은 대기자는 서버가 일괄 거절하므로 **목록을 다시 불러온다**(낙관적 갱신 금지) [제안, FE-5].
- 승인 시 정원 초과 같은 충돌은 서버가 거절할 수 있다 → 오류 후 목록 새로고침.

### 5.6 챌린지 만들기
필드와 검증 [확정]. 화면 배치는 피그마 "데일리 챌린지 만들기" 기반이며 **보완 필요 [디자인 필요]**.

| 항목 | 입력 | 규칙 |
|---|---|---|
| 챌린지명 | 텍스트 | **12자 제한** |
| 공개 여부 | 공개/비공개 | 개설 후 전환 불가 |
| 카테고리 | 단일 선택 | 운동·공부·커리어·독서·생활습관 |
| 목적 | 텍스트 영역 | |
| 공통 미션 | 텍스트 영역 | 하루 하나의 공통 미션 |
| 인증 방법·규칙 | 텍스트 영역 | 판정 기준. **변경 불가** |
| 기간 | 시작일·종료일 | **최소 7일** (종료일 ≥ 시작일+6일). 상한 미정 |
| 모집 정원 | 인원 선택 | 방장 포함. **공개 3~10, 비공개 2~10** |
| 바라는 점 | 텍스트(선택) | |
| 참여 포인트 사용 | 걸기/걸지 않기 | **공개에서만 노출**. 비공개 선택 시 이 영역 숨김 |
| 참여 포인트 금액 | 선택·입력 | 포인트 거는 공개에서만. **1,000~5,000P**, 개설 후 변경 불가 |

- 공개 ↔ 비공개를 바꿀 때 정원 하한(3 ↔ 2)·포인트 영역 표시를 즉시 갱신하고, 이미 입력한 값이 범위를 벗어나면 보정/경고.
- 개설 후 변경 불가 항목(공개 여부, 인증 규칙, 포인트, 정원 축소)은 **개설 버튼 근처에 한 번 안내** [제안, FE-6].
- 개설은 **동시 참여 5개 한도에 포함**된다. 이미 5개면 개설 불가 안내(문구 [OPEN, FE-O3]).
- 포인트 금액 단위(100P/500P/1,000P)와 시작일 최소값(오늘? 내일?)은 [OPEN, FE-O5]. 임시로 500P 단위, 오늘 이후 [제안].
- 개설 완료 화면·초대 링크/코드 공유 위치 [디자인 필요].

### 5.7 시작 보류 대응 — 방장 전용 [확정]
- 진입 3경로: ① 알림창 알림 → ② 홈 카드 → ③ 홈 카드 → 해당 챌린지 상세 상단. 모두 같은 두 선택지.
- 제목: `시작에 필요한 인원이 모이지 않았어요`
- 본문: `{챌린지명}의 참여 인원은 {현재인원}명으로, 최소 {최소인원}명이 필요해요. 총 3일의 추가 모집 기한이 주어져요. 3일 동안 최소 인원이 모집되면, 챌린지는 다음 날 자정부터 바로 시작해요. 3일 안에 선택하지 않으면 자동으로 폐기돼요.`
- 보조 정보: 기존 시작일·종료일, 현재 인원/최소 인원, 선택 기한(**예정 시작일을 포함한 3일째 23:59**, 예 "11월 3일 23:59까지").
- 버튼: `기간 다시 설정하기`(새 시작일·종료일, 최소 7일 규칙 동일) / `챌린지 폐기하기`(확인 필요, 폐기 시 참가자 포인트 즉시 전액 반환).
- **다른 시작 대기 참여자**에게는 보류 상태와 방장 결정 결과만 안내. 선택 버튼은 주지 않는다.
- 인원 수에는 **승인 대기 신청이 포함되지 않는다**(실제 합류한 인원만).
- 자동 폐기 화면 문구는 11절의 충돌 항목 참고.
- 시작 후에는 임의 폐기 기능이 **없다**. 시작 전 폐기 vs 진행 중 인원 미달 조기 종료를 혼동하지 않는다.

### 5.8 그룹 상세 (참여 중)
- 보여줄 것: **날짜별 인증 기록, 팀 달성률, 팀원 목록과 역할(방장·부방장 표식), 내 누적 실패 횟수**.
- 버튼: `인증하기`, `팀 채팅`. (판정은 별도 영역)
- 팀 달성률은 서버가 계산한 값을 표시한다. 클라이언트가 인증 개수로 재계산하지 않는다.
- 시작 전 그룹 상세에도 **본인의 부방장 표시와 역할 안내**를 제공한다.
- 조기 종료 예정이면 전날부터 안내(11절 #11).

#### 부방장 역할 안내 (그룹 상세 안 영역) [확정]
- 부방장 지정 알림을 누르면 해당 그룹 상세의 역할 안내 영역으로 이동.
- 제목: `{챌린지명}의 부방장 역할을 안내해 드려요`
- **포인트 없는 공개·비공개**에서는 "할 일" 4개(방장 인증만 확인 / 다음 날 12시까지 승인·거절 / 판정 결과 확인 / 본인도 매일 인증)와 "판정 기한을 놓치면?" 섹션을 보여준다.
- **포인트 공개**에서는 위 절차 대신 "운영진이 방장과 부방장을 포함한 모든 참여자의 인증을 판정해요. 판정 버튼과 업무 경고 규칙은 적용되지 않아요" 안내를 보여준다. ("판정 기한을 놓치면?" 섹션은 표시하지 않는다.)
- "방장이 이탈하면?" 섹션은 **공통 표시**.
- 안내 본문 전체는 화면정의서 §7 "부방장 역할 사전 안내" 원문을 그대로 쓴다 (문구 수정 금지, 변경 시 기획 확인).

### 5.9 인증 제출
- 보여줄 것: 오늘 미션, 인증 방법, **마감까지 남은 시간**(23:59 KST 기준).
- 버튼: `촬영`, `앨범에서 선택`. 촬영/선택 직후 **같은 화면에서** `다시 찍기` / `제출` (별도 확인 화면 없음).
- 제출 후: 포인트 공개 → **검수 중**, 그 외 → **보류**. 
- **제출 후 수정·삭제·재제출 불가** → 제출 전에 한 번 더 확인할 시각적 여지는 있되(미리보기), 제출 후에는 버튼 자체를 숨긴다.
- 하루 1건. 이미 제출했으면 `인증하기` 대신 상태 라벨을 보여준다.
- 인증 의무가 없는 날(퇴장 예정, 조기 종료 당일)은 제출 UI 비노출 [제안, FE-7].
- 마감(23:59) 이후 제출은 실패로 처리되므로 마감 후에는 제출 UI를 막고 서버 응답을 우선한다.
- 이미지 형식·용량·압축 [OPEN, FE-O5]. 클라이언트 리사이즈는 FE 재량(원본 비율 유지).

### 5.10 인증 판정 (방장·부방장, 비포인트 챌린지만)
- 보여줄 것: 제출자, 사진, 제출 시각, **인증 규칙**(판정 기준), 미처리 목록.
- 판정 대상 [확정]: 방장 = 자신 외 모든 팀원(부방장 포함) / 부방장 = **방장의 인증만**. **본인 인증은 본인이 판정 못 한다.**
- 버튼 `승인` / `거절`: **본인 역할에 해당하는 인증에만** 제공. 팀 피드 열람 권한과 판정 권한은 구분한다.
- 마감: 인증 다음 날 12:00. 판정 전엔 '보류'로 표시. 처리한 사진은 대기 목록에서 사라진다.
- 포인트 공개 챌린지: **판정 화면·판정하기 버튼·업무 경고 없음**.
- 판정 후 번복·재판정은 정의돼 있지 않다 → 승인/거절 전 확인 단계 여부 [OPEN, FE-O7].

- 정산 오류 시: "정산 처리 중" 상태 표시, 반환 포인트를 잔액에 더하지 않음 [제안, 백엔드 D-9].

## 6. 온보딩·마이페이지·설정

### 6.1 온보딩 (3화면) [확정]
흐름: 가입 완료·로그인 → **정보 입력** → `다음` → **이용 안내** → `확인했어요` → **완료·첫 가입 포인트 안내** → `완료` → 모집중 탭.
- 전체 건너뛰기 **없음**. 완료 전 중단 후 재진입하면 **첫 화면부터**.
- 화면 1: 닉네임(필수, 가입 시 값이 있으면 채워서 확인·수정), 한 줄 소개(선택), 관련 링크(선택), 관심 분야(**최소 1개, 복수 선택**, 필수). `다음` 클릭 시 필수값 검사. 프로필 사진은 여기서 받지 않는다(마이페이지에서).
- 화면 2: 접기/펼치기 3항목(챌린지 개설 및 참여 방법 / 포인트 습득 방법 / 팀 정산·모락이·메달) + `확인했어요`. 세 항목은 **한 화면 안에서** 펼치고 스크롤. **'확인했어요' 시점에 온보딩 완료 + 10,000P 1회 지급**. 본문 전체는 화면정의서 §온보딩 "세부 안내 내용" 원문 사용.
- 화면 3: `모락을 시작할 준비가 되었어요!` / `첫 가입 포인트 10,000P가 지급되었어요.` / `완료`. **실제 지급 완료 결과 기준으로 표시**. 재진입·버튼 중복으로 재지급 금지(→ 3.3).
- 별도의 온보딩 완료 추가 보상은 없다.

### 6.2 마이페이지 (위→아래 순서 고정) [확정]
1. 제목 `마이페이지` + 우측 상단 톱니바퀴(설정)
2. 프로필 사진(변경 표시) / 닉네임 / 한 줄 소개·관련 링크·관심 분야(태그) / `정보 수정`
3. 모락이 이미지 + `개인 인증률 N%` (+ 설명 아이콘 → 팝업)
4. `누적 완주 N회` · `중도 실패 챌린지 N회` 나란히 (+ 설명 아이콘)
5. `획득 메달` 자리 3개 + `메달 상세보기`
6. (본인 전용) `사용 가능한 포인트` `N P` + `포인트 내역`
7. `종료된 챌린지 전체 보기` 메뉴 행
8. **본문 최하단**: `승인 대기 중인 신청` 목록 (화면에 고정하지 않음, 스크롤 본문 맨 아래)
9. 하단 내비게이션 (마이페이지 선택 상태), 본문 끝과 겹치지 않게 하단 여백

- 한 줄 소개·링크는 **입력한 경우에만** 표시. 입력창을 상시 펼치지 않는다.
- 넓은 웹 화면에서도 읽는 순서와 "본인 전용 정보" 구분을 유지.
- 마이페이지에는 별도 '포인트 얻기' 버튼·획득 중간 화면을 두지 않는다.

### 6.3 프로필 사진 변경 [확정]
흐름: 사진 터치 → 기기 사진 선택 → (필요 시 접근 허용) → 선택 사진 확인 → `적용` / `취소` → 저장 성공 시 갱신.
- 취소하면 기존 사진 유지. PC는 파일 선택. 이미 선택창 접근이 허용되면 권한 요청을 반복하지 않는다.
- 접근 거부: `사진을 선택하려면 사진 접근을 허용해 주세요.` + `다시 시도` + `<`(마이페이지). 허용 방법 안내(설정 이동 지원은 환경에 따름).
- 저장 중: 처리 중 표시 + 중복 적용 방지. 성공 `프로필 사진이 변경되었어요.` / 실패 `사진을 저장하지 못했어요. 다시 시도해 주세요.` 실패한 사진을 저장 완료처럼 보이지 않게.
- 지원 형식·용량·자르기: 미정 [OPEN, FE-O5]. 이번 정의가 촬영·편집 도구 추가를 뜻하지 않는다.
- 사진 미설정 시 기본 프로필 이미지(모락이 이미지와는 별개).

### 6.4 정보 수정 [확정]
- 구성: `<` + `정보 수정` 제목, 기존 값이 채워진 닉네임·한 줄 소개·관련 링크·관심 분야, 하단 `변경 사항 저장`.
- 검증: 닉네임 비었음 → `닉네임을 입력해 주세요.` / 관심 분야 0개 → `관심 분야를 1개 이상 선택해 주세요.` (각 입력 **아래**에 표시, 저장 안 함).
- 성공 → 마이페이지로 돌아가 `변경 사항이 저장되었어요.` / 실패 → 입력값 유지 + 재시도.
- 닉네임 길이·중복·금칙어, 소개 길이, 링크 형식 검증 기준은 미정 [OPEN, FE-O5]. 서버가 검증 오류를 반환하면 해당 필드 아래에 표시하는 구조로 만든다 [제안].

### 6.5 모락이·개인 인증률·횟수 [확정]
- 모락이 이미지와 개인 인증률은 인접 배치. **팀 달성률·별도 완주율(%)은 개인 지표로 추가하지 않는다.**
- 설명 팝업 문구: `개인 인증률은 내가 해야 했던 인증 중 승인된 인증의 비율이에요. 사진을 제출하지 않은 날도 포함하며, 인증 의무가 면제된 날은 제외해요. 팀 달성률과는 달라요.`
- 모락이 단계: 95%↑ Stage5 / 85~95 Stage4 / 60~85 Stage3 / 30~60 Stage2 / 30↓ Stage1. **판정은 서버가 한 stage 값을 내려준다**. 클라이언트가 표시용(반올림된) 퍼센트로 단계를 계산하면 경계값에서 틀린다.
- 인증 기록이 전혀 없는 신규 사용자: `인증 기록 없음` + 기본 모락이. **0%·Stage1 표시 금지.** 안내 문구(제안): `챌린지에 참여하고 모락이를 활성화해 보세요!`
- 퍼센트 표시 자릿수는 미정 [OPEN, FE-O5].
- 완주/중도 실패 횟수 설명: 완주 = 퇴장 없이 예정 기간까지 참여한 챌린지당 1회, 중도 실패 = 개인 실패 누적으로 퇴장한 챌린지당 1회. **판정 업무 경고는 포함하지 않는다.** 조기 종료로 남은 사람은 두 숫자 모두 변하지 않는다.

### 6.6 메달 [확정]
- 마이페이지 영역: 자리 3개. **실제 획득한 메달만** 표시(미획득을 획득한 것처럼 채우지 않는다).
- `메달 상세보기` → 팝업이 아니라 **'메달 상세' 화면**. 세로 스크롤, 항목마다 메달 이미지·메달명/ID·획득 조건. 완주 조건 순.
- 누적 완주 1·3·5·10·20·30·50회에 지급, 최대 7종 보유, **새 메달이 이전 메달을 대체하지 않는다.**
- 메달 없음: `아직 획득한 메달이 없어요. 첫 챌린지를 완주하고 첫 메달을 받아보세요!`
- 마이페이지 3칸에 어떤 메달을 보여줄지(최신 3개? 높은 순?) [OPEN, FE-O10].

### 6.7 포인트 영역·내역 [확정]
- `포인트 내역` → 획득·사용·반환·차감 내역 화면 (상세 구성 [OPEN, FE-O11]).
- 내역 화면에 `광고 보고 받기` 버튼 + 광고 보상·일일 한도 안내(500P, 하루 5회). 선택 시 광고 시청 화면으로 바로 전환. 광고 완료 후 보상이 반영된 내역 화면으로 복귀. **중간에 닫으면 지급·횟수 차감 없음.**
- 앱 방문 출석 규칙은 내역에서 **안내만** 한다. **별도 '출석 완료' 버튼은 없다** (앱 진입 시 자동 출석, 하루 첫 방문 100P).
- 광고(MVP)는 모의 광고로 시작 가능 [제안, 백엔드 D-8]. 광고 화면 자체 [디자인 필요].

### 6.8 내 챌린지 전체 기록 [확정]
- `종료된 챌린지 전체 보기` → **내 챌린지 전체 기록** 목록: 과거에 참여한 챌린지(**정상 종료와 조기 종료 포함**, 목록에 "정상/조기" 구분 표시는 넣지 않는다). 진행 중 그룹은 홈에서만.
- 항목 선택 → **당시 상세**(챌린지명·기간·목적·미션·인증 규칙, 읽기 전용) → `과거 인증 사진 열람`, `과거 팀 채팅 열람` 두 버튼. 종료 후 사진 제출·채팅 작성 불가.
- 빈 상태: `아직 지난 챌린지 기록이 없어요.`
- 퇴장자는 실제 퇴장 시점까지의 채팅만 열람. 퇴장자의 인증 사진 범위·시작 전 폐기 그룹 열람 범위는 미정 [OPEN, FE-O8].
- 타인 프로필에는 이 메뉴를 표시하지 않는다.

### 6.9 승인 대기 목록 [확정]
- 항목: 챌린지명·예정 기간·`승인 대기` 상태. 선택 → 신청한 챌린지 상세. **신청 취소·탈퇴 버튼 없음.**
- 승인/거절이 확정되면 목록에서 제외. **5개 한도로 무효화된 신청도 유효한 대기로 표시하지 않는다.**
- 빈 목록: 제목은 유지 + `승인을 기다리는 신청이 없어요.`

### 6.10 설정 [확정/OPEN]
- 상단 메뉴: `알림 설정`, `이용약관`, `개인정보처리방침`. 하단: `로그아웃`, `회원 탈퇴`(구분 배치).
- 알림 설정: 앱 내 알림창이 기본 경로. **어떤 알림을 끌 수 있는지 미정 → "전체 알림 끄기" 토글을 임의로 만들지 않는다.**
- 로그아웃: **확인 팝업 없이** 바로 로그아웃하고 비회원 홈으로.
- 회원 탈퇴: 바로 처리하지 않고 안내·최종 확인 화면으로 이동. 탈퇴 조건(진행 중 챌린지·잔여 포인트·사진/채팅 보관) 정책이 미정이라 **안내문·최종 동작은 정책 확정 후** [OPEN, 백엔드 O-3]. BE 제안: 진행·시작 대기 중 챌린지가 있으면 탈퇴 불가 안내.

### 6.11 타인 프로필 (조회 전용) [확정]
- 보여주는 것: 기본 소개, 공개 개인 인증률·모락이, 메달, 누적 완주, 중도 실패.
- 보여주지 않는 것: 사진 변경, 정보 수정, 설정, 포인트, 종료된 챌린지 전체 보기, 개인 승인 대기 신청. **프로필 사진을 눌러 갤러리가 열리면 안 된다.**

## 7. 팀 채팅 [확정]

- 챌린지당 **팀 전체 채팅 1개**. 1:1 채팅·이미지 첨부 없음. 텍스트만. 메시지 수정/삭제/읽음 표시 없음.
- 진입: 승인(`ACTIVE`) 이후 **시작 전부터** 가능. 승인 대기자는 진입 불가.
- 레이아웃 (위→아래): 상단 `<`(이전 화면) / 챌린지명 / 날짜 구분선(`YYYY.MM.DD`, 날짜가 바뀌는 첫 메시지 앞) / 메시지 / 하단 입력창+전송.
- 메시지: **상대는 왼쪽, 본인은 오른쪽**. 상대 메시지에는 프로필 사진·닉네임·역할 표식(방장·부방장, 본인이 해당 역할이면 본인 닉네임에도) + 시각(`오전/오후 시:분`). 상대 프로필 선택 → 타인 프로필.
- **판정 업무 경고 시스템 안내**: 담당자 누적 2회부터 추가 경고 때마다 채팅에 시스템 메시지. 개인 미션 실패와 구분. (문구 [OPEN, FE-O12])
- 대화 없음: `첫 인사를 나누고, 함께할 도전을 응원해 보세요!`

**전송 상태**

| 상태 | 화면 | 처리 |
|---|---|---|
| 전송 중 | 메시지 옆 `전송 중`, 시각 미표시 | 같은 메시지 중복 전송 방지 |
| 성공 | `전송 중` 제거, 전송 시각 표시 | 읽음 여부와는 별개 |
| 실패 | 본문 유지 + `전송 실패` + `재전송` | 성공한 것처럼 표시 금지. 재전송은 같은 메시지로 다시 시도하며 **중복 게시하지 않음** |

- **`client_message_id` (UUID)를 메시지 생성 시 클라이언트가 만들고, 재전송 시 같은 값을 다시 보낸다.** 서버가 `(participation_id, client_message_id)`로 중복을 막는다. 새 메시지로 재전송하면 중복 게시가 된다.
- 작성 종료 후에는 재전송 불가.

**인증 스토리 답글**
- 인스타그램 스토리 답장 방식. 별도 사진 썸네일 카드로 표시하지 않는다.
- 답글 위에 인용 영역: `{닉네임}님의 인증 스토리에 답장` + 원본 인증 날짜, 그 아래 답글 텍스트. 한 개의 연결된 메시지로 읽히게.
- 인용 영역 선택 → 해당 인증 사진의 스토리 열람 화면. `<` → 기존 채팅 위치로 복귀(스크롤 위치 보존).
- 스토리의 답글 입력 영역 안내: `답글은 팀 전체 채팅방에 공개됩니다.`
- 퇴장자의 사진 열람 범위는 확대하지 않는다.

**작성 종료·퇴장 후**

| 상태 | 화면 |
|---|---|
| 정상·조기 종료 후 | **최종 결과 확정일 자정부터** 입력창·전송 버튼 대신 `종료된 챌린지의 채팅 기록입니다.` 끝까지 참여한 사용자는 기록 열람 가능 |
| 실제 퇴장 이후 | **퇴장 시점까지의 채팅만 읽기 전용**. 입력창·전송 대신 `퇴장 전까지의 채팅 기록만 확인할 수 있어요.` 이후 메시지·시스템 안내·알림 수신 없음. 새로고침·재진입해도 이후 대화 노출 금지. 답글 작성·실패 메시지 재전송도 제공하지 않음 |

- 퇴장 **공지일**과 **실제 퇴장일**은 다르다. 공지~퇴장 사이: 인증 의무는 면제지만 채팅 수신은 퇴장 시점까지 계속된다. 이 구간에서 전송 가능 여부는 BE 제안으로 **불가**(백엔드 D-11).
- 실시간 수신 방식(WebSocket/폴링/SSE)은 미정 [OPEN, FE-O13]. 먼저 폴링으로 시작해도 UX 영향은 적다.

## 8. 알림창

- 위치: 홈 우측 상단 종 아이콘 → 앱 내 알림창. **기본 전달 경로는 인앱.** 푸시 채널은 미정이라 푸시 의존 로직을 만들지 않는다.
- 포인트 문장(반환·차감)은 **포인트를 건 사람에게만** 붙는다. 서버가 문장을 포함해 내려줄지, FE가 플래그로 조립할지 [OPEN, FE-O14].
- 긴 안내(퇴장·조기 종료)는 알림을 누르면 상세를 보여준다.
- 알림 탭 이동 대상:

| 알림 | 이동 |
|---|---|
| 1 승인 / 2 거절 | 해당 챌린지 상세 (거절은 재지원 불가 상태) |
| 3 한도 초과 무효화 (방장) | 지원자 관리 + `확인` 버튼 |
| 4 시작 보류 (방장) | 시작 보류 대응 화면 |
| 5 기간 변경 / 6 폐기 / 7 자동 폐기 | 해당 챌린지 상세(폐기는 종료 상태) |
| 8 부방장 지정 | 그룹 상세의 부방장 역할 안내 영역 |
| 9 판정 경고 | 인증 판정 또는 알림 상세 |
| 10 퇴장 예정 | 퇴장 공지 상세 |
| 11 조기 종료 예정 | 조기 종료 안내 상세 |

- 읽음/안읽음 표시, 삭제 가능 여부 [OPEN, FE-O15].

## 9. 서버와 맞춰야 할 클라이언트 동작 (BE 위키 요약)

| 주제 | FE가 지킬 것 |
|---|---|
| 시간 | KST. 날짜는 `YYYY-MM-DD`(KST), 시각은 UTC 문자열 → KST로 변환해 표시. 자정 경계 계산을 클라이언트에서 하지 않는다 |
| 마감 카운트다운 | 서버 시각 기준(응답의 서버 시각과 차이 보정) [제안] |
| 포인트 계산 | 반환·차감·팀 달성률·개인 인증률·모락이 단계는 **서버 값 표시**. 반올림 규칙이 있어 FE 재계산 금지 |
| 중복 방지 | 3.3 목록 + 채팅 `client_message_id` |
| 신청 시 한도 | 5개 한도·잔액 부족은 서버가 거절한다. 사전 안내는 하되 최종 판단은 서버 응답 |
| 승인/거절 충돌 | 정원 마감·무효화로 서버가 거절할 수 있다 → 목록 새로고침 |
| 정원 가득 | 승인으로 정원이 차면 서버가 나머지 대기자를 자동 거절한다 |
| 상태 enum | 챌린지·참가·인증 상태는 서버 enum 값을 라벨로 매핑(4절). 알 수 없는 값이 오면 안전한 기본 표시 |
| 온보딩 | `onboarded_at` 이 비어 있으면 온보딩 3화면으로 보낸다 [제안] |

API 목록은 별도 문서 "모락 API 초안"(Claude Docs)을 따른다. 필드명은 거기를 우선한다.

## 11. 알림 문구 (FRD 기준) + 충돌 항목

`{ }`는 치환값. "포인트 시"는 포인트를 건 사람에게만 붙는 문장.

| # | 제목 | 본문 |
|---|---|---|
| 1 승인 | `{챌린지명} 참여가 확정됐어요` | `방장이 신청을 승인했어요. 팀원들과 인사를 나눠 보세요!` |
| 2 거절 | `{챌린지명} 신청이 승인되지 않았어요` | `이번 신청은 방장이 승인하지 않았어요. 다른 챌린지를 찾아보세요.` + (포인트 시) `걸어 둔 {포인트}P는 전액 반환됐어요.` |
| 3 한도 무효 (방장) | `{신청자명}님의 신청을 승인할 수 없어요` | `해당 사용자가 참여할 수 있는 챌린지가 초과되었습니다. 확인하면 승인 대기 목록에서 이 신청이 사라져요.` 버튼 `확인` |
| 4 시작 보류 (방장) | `{챌린지명}의 시작이 보류됐어요` | FRD 본문은 기획 메모 형태 → **5.7의 화면정의서 본문 사용** (충돌 ①) |
| 5 기간 변경 | `{챌린지명}의 기간이 변경됐어요` | `최소 인원이 모이지 않아 방장이 일정을 변경했어요. 새 기간은 {시작일}부터 {종료일}까지예요.` |
| 6 폐기 (방장 결정) | `{챌린지명}이 폐기됐어요` | `최소 인원이 모이지 않아 방장이 시작 전 챌린지를 폐기했어요.` + (포인트 시) 반환 문장 |
| 7 자동 폐기 | `{챌린지명}이 자동 폐기됐어요` | `시작 보류 후 3일 안에 기간 재설정이나 폐기가 결정되지 않아 자동 폐기됐어요.` + (포인트 시) 반환 문장 (충돌 ②) |
| 8 부방장 지정 | `{챌린지명}의 부방장이 되었어요!` | (충돌 ③) 아래 참고 |
| 9 판정 경고 | `{챌린지명} 판정 경고 누적 {횟수}회` | `{인증일} 인증을 기한 내 판정하지 않아 경고 1회가 추가됐어요. 미처리 인증은 자동 승인됐어요.` + (누적 2회↑) `누적 경고는 팀 채팅에도 안내됐어요.` |
| 10 퇴장 예정 | `{챌린지명}에서 퇴장 예정이에요` | `누적 인증 실패 {실패횟수}회로 퇴장 기준에 도달했어요. 오늘부터 인증 의무가 없으며, {퇴장일}에 퇴장 처리돼요.` + (포인트 시) `걸어 둔 {포인트}P는 전액 차감되며 반환되지 않아요.` |
| 11 조기 종료 예정 | `{챌린지명}이 조기 종료될 예정이에요` | `참여자가 2명만 남게 되어 {종료일}에 종료돼요. 종료 당일은 인증하지 않아도 되며, 회원님의 실패로 처리되지 않아요.` + (포인트 시) `종료 전날까지의 개인 인증 성공률로 정산해요. 걸어 둔 포인트의 최대 100%까지 반환되며, 추가 보상은 없어요.` / **상세**: `종료 전날까지의 개인 인증 실적은 유지돼요. 이 챌린지는 완주 횟수·메달·중도 실패 횟수에 추가되지 않으며, 과거 인증 사진과 채팅은 보관함에서 확인할 수 있어요.` |

- 퇴장일은 "내일"이 아니라 **실제 날짜**를 함께 표시한다.
- 포인트 공개 챌린지의 운영진 판정에는 #9가 적용되지 않는다.

**문서 간 문구 충돌 (기획 확인 필요)**
- **① 시작 보류 알림 #4 본문**: FRD는 규칙 설명 메모, 화면정의서는 화면 본문(5.7) 제공 → 5.7 본문을 알림 본문으로도 사용 [제안].
- **② 자동 폐기 #7**: FRD `…자동 폐기됐어요 / 시작 보류 후 3일 안에 …` vs 화면정의서 `챌린지가 자동 폐기 됐어요 / 최소 인원이 모이지 않아 시작 전 챌린지를 폐기했어요.` → FRD 문구 사용 [제안], 화면정의서 문구를 상세 화면 본문에.
- **③ 부방장 지정 #8 본문**:
  - FRD(비포인트): `첫 번째 팀원으로 합류해 부방장이 되었어요. 방장의 인증만 다음 날 낮 12시까지 승인하거나 거절해 주세요. 방장이 이탈하면 역할을 이어받아요.`
  - 화면정의서(비포인트): `첫 번째 팀원으로 합류해 부방장으로 지정되었어요. 방장의 인증을 다음 날 낮 12시까지 승인하거나 거절해 주세요. 방장이 이탈하면 방장 역할을 이어받아요. 자세한 역할을 확인해 주세요.`
  - 포인트 공개(FRD): `첫 번째 팀원으로 합류해 부방장이 되었어요. 인증은 운영진이 판정하며, 방장이 이탈하면 역할을 이어받아요.` / (화면정의서): `…이 챌린지의 인증은 운영진이 판정해요. …자세한 역할을 확인해 주세요.`
  - 제안: 화면정의서 쪽(알림 클릭 유도 문장 포함)을 사용.
- **④ 판정 경고 공개 기준**: FRD 용어표 "3회" 표기는 오기. 모든 화면은 **누적 2회부터**.

## 12. 프론트 OPEN / 디자인 필요 / 확인 질문

### 12.1 [디자인 필요] 화면 정의 자체가 없는 것
1. 하단 내비게이션 구성(탭 몇 개, 이름) — FE-O1
2. 챌린지 만들기 화면 보완(피그마), 개설 완료 화면, **초대 링크·코드를 방장이 확인/공유하는 위치**
3. 광고 시청 화면(모의/실광고 포함)
4. 어드민(운영진 검수) 화면 전체
5. 챌린지 최종 결과 화면(정상/조기/퇴장별 변형)
6. 비로그인 사용자 홈·탐색 화면
7. 포인트 내역 화면 구성(획득/사용/반환/차감 항목 단위)
8. 알림창 목록 UI(읽음/안읽음, 삭제)
9. 판정 화면(방장·부방장) 레이아웃
10. 회원 탈퇴 안내·최종 확인 화면

### 12.3 BE 쪽에서 아직 정해지지 않아 FE에 영향이 있는 것 (백엔드 위키 OPEN과 연결)
- 운영진 검수 마감과 어드민 범위(O-1, O-2) → 5.13, 결과 화면 타이밍
- 방장 이탈 트리거·회원 탈퇴 정책(O-3) → 6.10 탈퇴 화면
- 챌린지 기간 상한(O-4) → 5.6 날짜 선택 제한
- 초대 코드 길이(O-5) → 초대 코드 입력 필드
- 승인 후 시작 전 탈퇴(O-6), 비공개 1명 남음(O-8), 푸시 채널(O-10), 광고(O-11)

## 13. 구현 체크리스트 (스프린트 쪼개기용)

1. **인증/온보딩**: 로그인, 온보딩 3화면, 가입 포인트 1회 지급 중복 방지
2. **탐색·상세·지원**: 모집중, 상세 버튼 상태 매트릭스(4.2), 지원서, 포인트 확인(5.4), 승인 대기
3. **개설**: 만들기 폼 검증(5.6), 개설 후 불변 항목 안내
4. **방장 도구**: 지원자 관리(5.5), 시작 보류 대응(5.7), 초대 링크 공유
5. **홈·그룹**: 카드 상태(4.1), 그룹 상세, 부방장 역할 안내
6. **인증**: 제출(5.9), 판정(5.10), 피드/스토리, 라벨(4.3)
7. **채팅**: 7절 (전송 상태 3종, `client_message_id`, 종료/퇴장 화면)
8. **알림창**: 8절 + 11절 문구
9. **결과·기록**: 최종 결과(5.12), 내 챌린지 전체 기록(6.8)
10. **마이페이지**: 6.2~6.7, 메달, 포인트 내역·광고, 설정
11. **어드민**: 5.13 (정책 확정 후)

> 구현 중 문서와 화면이 어긋나면 이 위키를 먼저 고치고, 그다음 화면정의서·API 문서에 반영한다.
